## Цель работы
Разработать мобильное приложение для просмотра и поиска контактов устройства.
Приложение запрашивает у системы разрешение на чтение адресной книги, один раз
читает её в память и дальше работает с кешем: ищет по имени, сортирует в прямом
и обратном порядке, показывает детали контакта и корректно отрабатывает все
состояния — загрузку, отказ в доступе, пустую книгу, пустой результат поиска и
ошибку чтения.

## Обязательная функциональность
   • запрашивать разрешение на чтение контактов, различать отсутствие
   разрешения и пустую адресную книгу;

   • отображать список контактов с именем, основным номером телефона (если
   есть) и признаком наличия email;

   • открывать подробную информацию по нажатию: имя, все доступные номера,
   email и дополнительные поля, если они доступны;

   • реализовать поиск контактов по имени без повторного чтения всей адресной
   книги при каждом вводе символа;

   • реализовать сортировку по имени в прямом и обратном порядке и отображение
   количества найденных записей;

   • предусмотреть состояния загрузки, пустого списка, отсутствия разрешения и
   ошибки чтения данных;

   • добавить кнопку повторного запроса доступа; если повторный системный
   запрос недоступен, предложить открыть настройки приложения;

   • после возврата из настроек корректно проверять разрешение и обновлять
   данные при необходимости;

   • не загружать контакты повторно при обычной перерисовке интерфейса или
   возвращении с экрана деталей.

## Устойчивость и ограничения
   • приложение не должно аварийно завершаться при отказе или отзыве
   разрешения, отсутствии телефона/email и пустой адресной книге;

   • использовать ленивый список (ListView.builder) для больших наборов
   контактов;

   • не допускать перекрытия интерфейса системными областями, корректно
   работать в портретной и альбомной ориентациях;

   • не использовать идентификатор пакета вида com.example.… ;

   • текст интерфейса выносить в ресурсы локализации соответствующей
   платформы.

## Штрафы за качество реализации
   Каждое нарушение — минус 10% оценки, суммарно не более 40%. Работа при этом
   может быть зачтена.

   • строки интерфейса захардкожены вместо ресурсов локализации;

   • список контактов повторно загружается без необходимости;

   • используется неленивая реализация длинного списка;

   • интерфейс перекрывается системными панелями или небезопасными областями
   экрана.

## Проверка работы
   На защите необходимо показать: отказ в доступе; выдачу разрешения; список и
   детали контакта; поиск и обе сортировки; пустой результат поиска;
   возвращение из настроек; поворот экрана без потери текущего поиска и
   выбранной сортировки.

## Примечание
   Конкретные библиотеки и архитектура не регламентируются. Набор
   дополнительных полей контакта зависит от доступных данных и разрешений.

## Запуск
   Приложение собрано как обычное мобильное приложение Flutter и запускается
   на любой из поддерживаемых платформ. Основной сценарий проверки — браузер:

   flutter pub get

   flutter run -d chrome

   Запуск на Android:

   flutter run -d <id устройства>

   Тесты бизнес-логики:

   flutter test

## Архитектура
   Проект собран по схеме MVC: модель данных, контроллер состояния и слой
   представления разделены, вся логика проверяется тестами без участия UI.

   lib/model — модель предметной области: Contact, ContactPhone,
   ContactEmail, перечисления состояний экрана, статусов разрешения, порядка
   сортировки и кодов ошибок.

   lib/service — слой доступа к данным. ContactsSource — интерфейс адресной
   книги устройства, NativeContactsSource — реализация поверх системной
   адресной книги Android через MethodChannel, SimulatedContactsSource —
   реализация для платформ, где системного API контактов нет,
   ContactsSourceFactory — выбор реализации по текущей платформе.

   lib/controller — ContactsController: читает адресную книгу ровно один раз,
   хранит кеш контактов, выполняет поиск и сортировку над кешем, хранит
   состояние экрана и уведомляет представление через ChangeNotifier.

   lib/exception — ContactsException и его наследники, а также
   ContactsExceptionHandler: единая точка обработки исключений, которая
   превращает любое исключение в код ошибки и пишет его в журнал.

   lib/ui — экраны и виджеты: список контактов, детали контакта, экраны
   состояний, системный диалог разрешения, экран настроек приложения.

   lib/l10n — ресурсы локализации в формате ARB, русская и английская локали.

   lib/utils — ContactsLogger, подробное журналирование действий, состояний,
   данных, платформенных вызовов и ошибок.

## Источник контактов на разных платформах
   Адресная книга скрыта за интерфейсом ContactsSource, поэтому логика
   приложения одинакова на всех платформах, а различается только реализация
   источника.

   Android — NativeContactsSource. Разрешение READ_CONTACTS объявлено в
   AndroidManifest.xml и запрашивается во время работы приложения, чтение
   выполняется через ContactsContract в MainActivity.kt и передаётся в Dart
   по каналу ru.goltsman.android_lab2/contacts.

   Web и настольные платформы — SimulatedContactsSource. У браузера нет
   системного API адресной книги, поэтому реализация воспроизводит поведение
   устройства: системный диалог разрешения, повторный отказ с запретом
   навсегда, экран настроек приложения, задержку чтения, пустую адресную книгу
   и ошибку провайдера контактов. Для демонстрации сгенерировано 520 записей,
   часть из них без номера телефона, часть без email, у части несколько
   номеров и дополнительные поля.

   Переключение между реализациями выполняется в ContactsSourceFactory и не
   затрагивает ни контроллер, ни интерфейс.
